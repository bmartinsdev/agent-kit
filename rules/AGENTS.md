# Global Workflow, Git Discipline & Hybrid Workforce Protocol

## 1. Git & Hook Discipline
- **Never Commit Without Explicit User Approval**: Never run raw `git commit`, `git push`, or `git add` directly (enforced via `agent-kit` `PreToolUse` hook). Once the user explicitly approves the completed work or asks to close/commit the change, activate the **`close-change`** skill (`commit-approved-change.sh`) to stage changes, run pre-commit hooks, and create the commit.
- **Do Not Proactively Run Format or Pre-Commit Test Commands**: Running full test suites (`pnpm run test`, etc.) and code formatters (`pnpm run format`, `prettier --write`, `gofmt -w`) is handled automatically by git pre-commit hooks during `close-change`. Avoid running these commands manually after routine coding steps unless explicitly asked by the user or actively debugging a specific test file you are writing.
- **Respect Conditional & Scoped Rules**: Always check the active workspace's `.agents/AGENTS.md` and directory-scoped `AGENTS.md` files (which include stack-specific rules from `~/.gemini/config/plugins/agent-kit/rules-library/`) to follow project-specific paths, design tokens, and architecture boundaries.

## 2. Hybrid Workforce Orchestration
- **Quick Tasks (Direct Execution)**: Handle single-file fixes, targeted edits, and quick questions directly in the main conversation while following relevant skills.
- **Multi-Step Features, Redesigns & Audits (Subagent Delegation)**: When tackling a feature that spans multiple layers (Backend + Frontend + Tests + Docs), a multi-screen UI redesign, or a broad repository audit, activate the **`workforce-orchestrator`** skill to coordinate specialist subagents (`ui-designer`, `backend-architect`, `qa-architect`, `docs-keeper`, `code-reviewer`, `change-closer`) with explicit handoff contracts.
- **Mandatory Multi-Agent Task Re-Evaluation Gate**: Whenever picking up a task specification from `tasks/` or starting a milestone, NEVER jump straight into implementation. First spawn all relevant specialist subagents (`backend-architect`, `ui-designer`, `qa-architect`, `docs-keeper`) in read-only audit mode to compare the `tasks/*.md` spec against the current codebase and surface domain-specific questions. Consolidate their questions (tagged by agent role, e.g., `[backend-architect]`, `[qa-architect]`) and present them to the user via `ask_question` with `(Recommended)` defaults. Update the task spec with the user's decisions before launching implementation.
- **Mandatory `code-reviewer` Subagent Gate (Pre-Handoff & Post-Pivot)**: Before presenting completed multi-file work to the user—and **mandatory after any mid-task user requirement change or scope reduction**—spawn the **`code-reviewer`** subagent (`invoke_subagent(TypeName: "code-reviewer", ...)`) to audit the full `git diff` and working tree across all layers (Backend interfaces/handlers, Frontend components/providers, Tests, and Docs) for leftover/orphaned code from earlier iterations, redundant wrappers, and unreferenced untracked files. Fix all `[BLOCKER]` and `[WARNING]` findings before presenting the summary to the user.
- **Mandatory Pre-Approval Summary & Manual Testing Guide**: After `code-reviewer` passes and before asking the user to approve or close a change, ALWAYS present a structured **Summary of Changes & Manual Testing Guide** containing: (1) a grouped summary of what changed with clickable file links, (2) step-by-step manual testing instructions (how to start the dev server, what to check in the UI Playground `/kitchen`, and what user flows to test in the main app), and (3) automated verification results.
- **Post-Approval Change Closure (`close-change`)**: After presenting the Summary of Changes & Manual Testing Guide and receiving the user's explicit approval, run the **`close-change`** skill (`commit-approved-change.sh`) to finalize and commit the changes cleanly.
- **`agent-kit` PR & README Sync (`kit-evolver`)**: Whenever evolving `agent-kit` (`agents/`, `skills/`, `rules/`, `rules-library/`, or `hooks.json`), always update `~/.gemini/config/plugins/agent-kit/README.md` in the same PR so its counts, Mermaid diagram, and cheatsheet stay 100% in sync.
